## 2. 自进化核心机制

天机妙策局的核心优势在于**持续的自进化能力**，避免了传统 Prompt 系统的静态僵化。

### 2.1 动态特邀专家 (Phase 2.5)
在大纲通过后，主理人诸葛亮与架构师鲁肃自动评估当前课题。若课题极度前沿或垂直（例如：核聚变、量子密钥、深地油气技术等），系统会自动进化出一名特定背景的**虚拟特邀专家（第 13 位成员）**并挂载专属视角，在后续章节研究中参与撰写，从而提供最前沿的行业洞察。

### 2.2 复盘与进化日志 (Phase 6)
最终报告交付后，团队不会立即解散，而是启动 Phase 6 闭环复盘：
1. 徐庶与曹植梳理审稿驳回记录，发现本次研究中体现出的数据劣势或政策盲点。
2. 提炼出 1-3 条高可用的**进化规约 (Evolutionary Protocols)** 并呈现给用户。
3. 用户将其复制并追加至项目根目录下的 `cross-platform/evolution_log.md` 文件的 `## 🛠️ 进化规约` 列表中。
4. 下一次启动天机妙策局时，AI 会自动前置加载该日志，完成自进化迭代。

## 3. 三种使用方式

### 方式一 · 复制即用（最通用）
**适用工具**：ChatGPT / Claude / DeepSeek / Kimi / 腾讯元宝 / 通义千问 / 豆包 / WorkBuddy 对话框等。
1. 打开 `cross-platform/orchestrator.md`，**全选并复制**全部内容。
2. 粘贴到 AI 工具或 WorkBuddy 的对话框。
3. 在下方直接输入研究需求（例如：`帮我深度调研中国能源央企数字化转型的现状、挑战与路径`）发送。

### 方式二 · 文件加载（IDE 自动激活）
**适用工具**：Cursor / Claude Code / CodeBuddy / Trae Solo / Windsurf / Copilot / Antigravity 等。
将 `cross-platform/` 下的配置文件放在项目根目录，工具会**自动读取**：
- Cursor 读取 `.cursorrules`
- Claude Code 读取 `CLAUDE.md`
- CodeBuddy 读取 `CODEBUDDY.md`
- Gemini / Antigravity 读取 `.gemini/instructions.md`

### 方式三 · 插件导入（WorkBuddy 专属）
1. 打开项目根目录下的 `expert/tianji-my-expert.zip` 压缩包。
2. 在 WorkBuddy 专家中心导入该 zip 插件包。
3. 切换到“天机妙策局”专家面板，即可开始 12+1 位三国谋士的智能流水线自进化深度研究。

## 4. 各平台详细操作

*对于 Web 版 AI（如 Claude, DeepSeek）*，粘贴 Prompt 后，AI 会扮演主理人诸葛亮自动向下调度，中途如遇截断，只需回复“**继续**”即可。
*对于 IDE（如 Cursor）*，可以直接使用 `@` 提及团队文件，或通过项目全局规则自动生效。如果希望手动引入进化日志，在提问时可加上“*参考 `cross-platform/evolution_log.md` 的最新进化规约进行研究*”。

## 5. 研究流程详解 (6 阶段)

### Phase 1：五线并行调研
主理人诸葛亮依次调度 5 位专业研究员完成对课题的深度扫描：
- **贾诩**（政策扫描）、**荀彧**（经营与站位扫描）、**周瑜**（行业对标扫描）、**郭嘉**（数据扫描）、**马钧**（专利格局扫描）。
- 汇聚并输出一份五线合一的**统一研究摘要**。

### Phase 2：大纲规划
鲁肃基于调研摘要，规划章节大纲（JSON 结构），并请用户确认。

### Phase 2.5：特邀专家进化评估
如果判定课题为前沿/交叉科学，自动生成一名特邀专家（如蒲元、华佗化身等），并赋予专属职责。

### Phase 3：逐章研究（审稿修订循环）
对每个章节，分派给最契合的角色或特邀专家进行深度撰写（800-1500 字，要求带真实引用链接）。
撰写后，由**徐庶**进行 7 维严格审稿。若输出为 `REVISE`，则由**曹植**修改，最多迭代 3 轮后强制通过。

### Phase 4：战略洞察与报告框架
**司马懿**结合荀彧的政治站位分析，输出 SWOT、战略建议、风险评估与路线图。**陈琳**撰写引言、结论及参考文献排版。

### Phase 5：最终交付
整合全部成果，由陈琳完成排版并输出完整的高质量 Markdown 报告。

### Phase 6：复盘与自我进化
主编诸葛亮主持复盘，导出进化规约并通报用户更新 `evolution_log.md`。

## 6. 支持的输出类型

- 📊 **研究报告（默认）**：针对行业分析、政策解读、对标分析，采用标准 6 阶段起承转合结构。
- 🗓️ **定期工作汇报**：月报、季报、年报、年度工作总结。采用 `工作成效亮点 -> 指标达成对标 -> 面临问题瓶颈 -> 下步重点计划` 的经典框架。
- 🎯 **工作专项汇报**：专项报告、专题总结。采用 `专项背景大局 -> 推进举措实效 -> 难点堵点诊断 -> 后续保障建议` 的针对性攻坚框架。
- 📋 **项目实施方案**：加设里程碑规划、技术实施路径和保障措施。
- 🔍 **专利分析**：重点对标专利格局与布局策略。
- 📝 **专利交底书**：严格按 CNIPA 格式要求产出 6 章专利交底书与 Mermaid 图示。
- 📚 **学术论文**：侧重理论文献综述和严密的学术范式与参考文献格式。
- ⚡ **快速汇报/研究**：缩减至 3 章并跳过徐庶审稿环节以提升生成速度。

## 7. 最佳实践与常见问题

### 好的研究提问
> 帮我深度调研中国新能源汽车央企（重点关注一汽、东风、长安）的科技创新路径，并与特斯拉、比亚迪进行国际对标。

### 常见问题
- **Q: 为什么提示某些数据找不到？**
  答：部分央企未公开核心财务数据，天机妙策局绝不编造，会如实声明“来源不足”并在报告末尾列为待完善事项。
- **Q: 审稿一直不过怎么办？**
  答：系统内置最多 3 轮循环。若 3 轮后仍有小瑕疵，徐庶会强制 PASS 并将未决问题列在“审稿警告”中。
- **Q: 进化日志必须手动更新吗？**
  答：在 Web 端交互时需要手动追加到文件。在部分支持自动文件写入的 Agent 环境中，主理人诸葛亮会直接自动更新 `evolution_log.md`。
